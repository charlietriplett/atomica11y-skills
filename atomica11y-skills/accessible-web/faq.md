# Web FAQ skills



## How to test a faq 

Given that I am on a screen with a faq

### 1. Keyboard only

- WHEN I use the arrow keys or tab key

  - I SEE nothing, because we don't use FAQ


### 2. Desktop screenreader

- WHEN I use a desktop screenreader (NVDA, JAWS, VoiceOver) AND I use the arrow keys or tab key

  - I HEAR nothing, because we don&#39;t use faq


### 3. Mobile screenreader

- WHEN I use a screenreader AND I swipe

  - I HEAR nothing, because we don&#39;t use faq


## Component intent and decision matrix

Data for deciding which components to use for what purposes.

### When to use a FAQ

FAQ usage guidelines provide insight into when and how to use a component effectively, ensuring that it serves its intended purpose.

- Do not use an FAQ. Instead, invest in better UX copywriting and put detailed information where people originate questions, rather than a central mystery meat FAQ page.


### Antipatterns not to use

Antipatterns are common misuses of a component that lead to poor user experience, overly complicated code and accessibility issues. Being aware of these helps you avoid them and use a faq more effectively.

- Do not use custom implementations that break native keyboard interaction for expanding/collapsing.


### FAQ misconceptions

Commonly repeated myths or false beliefs lead to confusion or misuse of a faq. Examine these myths to ensure you're using the component correctly and effectively, even when people repeat a myth as fact.

- Users do not read all FAQs. If your app is difficult to understand, a dedicated page of questions is a subpar approach to helping the user.
